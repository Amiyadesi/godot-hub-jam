# ADR 0001：实体维护焦点

- 状态：Accepted
- 日期：2026-07-21

## 背景

实体因果管线已经从旧网格墙板迁入真实关卡，但仅按玩家与模块的最近距离直接操作会产生三个问题：高处设备可能不可达，多个相邻插槽容易误选，玩家也无法稳定读出 authored 导管拓扑。恢复 modal 网格或独立镜头又会把谜题重新变成背景上叠着的小游戏。

## 决定

采用“实体维护焦点”。陆衡必须在管线底部 authored `Breaker/InteractionPoint` 附近进入；进入后世界、角色和设备保持可见，陆衡停止移动，方向输入只沿 `connected_socket_ids` 选择实体目标。

- 首次 `J` 只进入焦点，不同时操作。
- `J` 操作当前插槽或总闸，`K` 旋转，`L` 退出。
- 总闸作为虚拟目标连接最近 enabled 插槽。
- fixed 插槽参与导航并作为暖灰地标，但拒绝 `J/K` 状态变更。
- 磁力物体和普通机关继续使用独立的近距离交互，不进入管线焦点。

## 放弃方案

- 最近距离直接操作：在密集、高位或分支管线中不可预测，也无法保证每个 authored 目标可达。
- 旧 modal 网格：切断角色、房间和因果设备之间的空间关系。
- 准星或全屏覆盖层：会把真实设施重新抽象成 UI，并遮挡双空间观察。

## 后果

- 房间必须维护稳定、互相可达的 `socket_id` 和双向 `connected_socket_ids`。
- 管线入口、磁力物体和普通机关分别采用约 `220px`、`190px`、`180px` 的交互距离。
- 角色切换、死亡、复位、禁用和离场必须显式结束焦点并清理描边。
- 焦点期间 `L` 不冲刺；退出后恢复原有冲刺行为。
- UI keyboard focus 与实体维护焦点是两个独立概念，文档和代码不得混称。
