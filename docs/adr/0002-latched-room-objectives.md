# ADR 0002：房间目标记录锁存的历史事实

- 状态：Accepted
- 日期：2026-07-21

## 背景

实体管线按 `CircuitRunPlan` 发送开启与关闭边沿。某个设备达到正确状态后，后续反向边沿可能让它回到原位。如果房间完成条件直接读取当前瞬时电平，玩家已经完成的移动验证会被擦除，Ch2 R1 也会在升降台或护盾恢复后失去通关条件。

这种行为与《迟相》的因果表达冲突：正确结果一旦抵达并被角色验证，就已经成为本房间发生过的历史事实。

## 决定

区分设备锁存与房间完成印记。

- `PoweredDevice.latch_effective_state = -1` 保留普通边沿行为。
- `0` 锁存第一次有效关闭，`1` 锁存第一次有效开启；后续相反边沿不再改变设备有效状态。
- `capture_persistent_state()` / `restore_persistent_state()` 保存已经抵达的锁存状态。
- `_room_progress` 只在正确 link 值抵达时写入；后续相反值不删除完成印记。
- 只有房间明确复位、失败重建或新房间载入才清除对应状态。
- Ch2 R1 的陆衡升降台锁存开启，星遥护盾锁存关闭；`ch2_r1_shield` 与 `ch2_r1_xing_exit` 都成立后才开放出口。

## 放弃方案

- 直接读取当前电平：关闭沿会撤销玩家已经完成的目标，导致出口反复锁死。
- 延长脉冲或增加宽松计时器：只掩盖竞态，不能表达“已经发生”的历史事实。
- 由 HUD 保存勾选状态：把玩法真相放进显示层，无法参与 checkpoint 和房间复位。

## 后果

- 设备当前状态与房间完成印记成为两个明确概念，不能混用。
- 需要可逆机关的房间继续使用 `latch_effective_state = -1`。
- 稳定 checkpoint 只保存已经抵达的设备锁存；不保存事件队列或中途倒计时。
- 新房间设计必须明确哪些目标是持续电平，哪些目标是一旦成立就不可撤销的历史事实。
