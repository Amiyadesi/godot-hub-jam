# 《迟相 / Phase Lag》UI 与动效方向

## 目标

UI 应像设施本身的校准界面：克制、可读、带少量技术感，但不以强闪烁、鼠标追光或满屏故障特效抢夺注意力。所有样式、布局和动画都由 `.tscn`、`Theme`、`StyleBox` 与 `AnimationPlayer` 创作；脚本只切换状态和播放已有动画。

## 参考网站提炼

以下参考只提炼视觉原则，不复制网页结构：

- [Anime.js](https://animejs.com/)：一个明确的运动焦点优于许多同时发光的小元素；环、轨迹和节拍必须表达状态变化。
- [Robin Payot](https://robinpayot.com/)：大面积留白、单一入口和稳定中心能建立仪式感；《迟相》借用“先校准、再进入”的节奏，不照搬强制入口页。
- [Lando Norris](https://landonorris.com/)：大胆主视觉与极少导航形成强层级；《迟相》把大标题和命令列分开，不让每个按钮都争夺第一视觉层。
- [Bentolio](https://bentolio.vercel.app/)：编辑式不对称和清楚分区能让大量信息保持秩序；设置页与按键页可以借用分区节奏，不使用与游戏无关的网页卡片堆叠。
- [Infinite Imaginations](https://oninross.github.io/infinite-imaginations/)：粗细明确的边框、标签与块面适合键盘/手柄焦点；项目采用稳定描边和左侧强调条，不使用模糊光晕代替选中态。
- [Active Theory](https://activetheory.net/)：黑场、负空间和单一精密物件能制造空间感；项目只保留低频环境运动和一次相位校准，不复制粒子海、定制光标或长加载演出。

## 主菜单：方案 A「相位校准」

- 左上：大标题“迟相”，`PHASE LAG // CAUSAL CALIBRATION` 作为小型技术标记。
- 右下：约 `370px` 宽的窄命令列；按钮高度约 `50px`，间距 `10px`。
- 背景：保留 Ansimuz 走廊，只使用暗色遮罩、一次同图层轻微错位和低强度光线变化。
- 正常入场：约 `1.45s`。背景由失锁到稳定，标题先建立，按钮以约 `0.10s` 间隔依次出现。
- `low_flash_mode`：约 `0.32s`，只保留短淡入，不播放明显错位或亮度峰值。
- 第一枚离散输入只跳到动画终帧；第二枚输入才激活当前按钮。
- 动画期间不能出现白场、整屏亮闪、文字倍亮、随机旋转、鼠标追光或持续辉光。
- 菜单进入完成后，焦点描边稳定存在；hover 与键盘/手柄 focus 使用同一视觉语言。

## 运动令牌

| 场景 | 时长 | 规则 |
| --- | ---: | --- |
| 按钮 hover/focus | `0.16s` | 只改变描边强度，不改变布局、不随机旋转。 |
| 按下 | `0.09–0.16s` | 最大压缩约 `0.985`，随后回到 `1.0`。 |
| 普通 modal 进入 | `0.22–0.32s` | 位移不超过 `24px`，伴随淡入。 |
| 普通 modal 退出 | 进入的 `60–70%` | 更快离开，立即归还焦点。 |
| 主菜单校准 | `1.2–1.6s` | 只允许一个主运动焦点，必须可跳过。 |
| reduced motion | `0–0.32s` | 取消视差、错位和高对比闪断。 |

任何淡出元素在低于 `0.2` 不透明度后应迅速完全隐藏，避免长时间残影。常规界面一次最多同时运行两种视觉系统，例如“背景轻移 + 命令列淡入”。

## 设置控件

- `CheckButton`：必须有 authored 的 off、on、hover、pressed、focus、disabled 图形；开关状态不能只依赖颜色。
- `HSlider`：使用方形或菱形 grabber，补齐 normal、hover、pressed/highlight；禁止出现 Godot 默认灰色圆球。
- `OptionButton` 与内部 `PopupMenu`：共用面板、字体、边框、hover、disabled 与 separator 主题；下拉层不能退回默认 Theme。
- 页面脚本不得创建 `StyleBox`、Theme、节点或运行时布局。
- 焦点环要在冷暖背景上都满足清楚辨识；禁止用大面积发光框遮住文字。

## 按键页

- 列表最大宽约 `560px`；动作列 `180px`，列间距 `16px`，键位列占剩余空间。
- 每行使用 authored `PanelContainer`，内边距 `12px`，行距 `8–10px`。
- 当前行使用左侧强调条和细边框；hover 时该行按钮立即 `grab_focus()`，鼠标向下移动时焦点框必须跟随。
- 动作名与键位距离要近，不能横跨大面积空白；每行仍需留出足够区别，避免读错对应关系。
- 常驻键位条不进入游戏世界；交互键只在接近目标且确实可执行时出现。

## 局内信息层级

1. 角色、敌人攻击预警、可交互道具。
2. 门、平台、护盾与在途/抵达状态。
3. 短暂交互提示和 radio bark。
4. 装饰性环境运动。

瞄准与选中只使用贴合对象轮廓的描边。禁止巨型准星、整块泛光、全屏暗角脉冲或遮住手持物的焦点框。Ch2 始终 `1:1` 分屏；玩法占比通过任务节拍表达，不通过压缩某一侧画面表达。

## 禁止项

- 网页式 hero/CTA 套板直接移植到游戏。
- 白闪、频闪、扫描线轰炸、RGB 分离常驻、鼠标跟随聚光。
- 每个按钮不同颜色、不同圆角、不同运动曲线。
- 运行时生成 UI 样式或缺失节点的静默 fallback。
- 用大段教程文字解释本可由场景、动画和声音表达的机制。
